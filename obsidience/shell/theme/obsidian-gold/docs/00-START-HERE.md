# Start here: a coherent shell, not a screenshot skin

The approved visual direction is fixed: matte black/charcoal cassette-futurist panels with warm brass outlines, restrained gold selection, off-white reading text and low-contrast geometric arcs confined to chrome. The 1980s/1990s starship influence is structural: modularity, serviceability, purposeful seams, material discipline and readable instruments. It is not a collection of Starfleet logos, star dates or LCARS elbows.

## Review order

Open the atlas at `../preview/index.html`. Begin with Desktop overview, Computer, Reader, Graph, Hardware, Terminal and Appearance. Then review Quick settings, Notifications, Displays and Permissions. Use the state selector to inspect Ready, Empty, Service unavailable and Needs approval. Use the implementation-notes button for the exact component path, stable pane identity and authority boundary.

The left rail and top surface selector are **atlas navigation**. They are not a proposal to put a 53-item permanent menu inside every native pane. Real panes retain the existing launcher, native chrome and placement contracts. Desktop overview and Development are workspace compositions, not new independent engines.

## Design scope

All 16 registered native panes are covered. Graph Knowledge/Memory/Code share one native pane. Existing Settings Graph/Input/Workspace/AI & Voice remain sections of one Settings pane. Proposed desktop controls become settings sections, transient shell surfaces or supported external-tool integrations as appropriate.

Native capabilities are not inferred from prototype buttons. Existing means the underlying pane/owner was found in source; it does not mean this new visual design is deployed. Missing presentation means the desktop service or capability may already exist underneath. Design only means neither a functional implementation nor security approval is implied.

## Completion boundary

This delivery establishes the first theme package and full design plan. It intentionally does not interrupt running tasks, coding sessions, the secure locker, camera use, graphics outputs or model residency. Full coherent native activation is a separate, ordered implementation pass through the existing owners, with real acceptance checks rather than cosmetic success claims.
