# Query Runbook (Alexandria)

## Prerequisites
- An active `Tasks/query` session with an activation briefing.
- Access to the provided Tools and Skills.

## Ordered Actions
1. **Analyze Briefing**: Read the activation briefing to identify the core question and any specific constraints or context.
2. **Information Retrieval**:
   - Use `vault.search` to find relevant articles by meaning.
   - Use `vault.list` to enumerate specific folders if the query context suggests a known location.
   - Use `vault.read` on exact references found to obtain full context.
3. **Evidence Verification**:
   - If the answer relies on research findings, use `source.read` to verify the content against the original source.
4. **Synthesis**:
   - Formulate a concise, grounded answer based on the retrieved evidence.
   - If the answer requires updating the vault, use `vault.propose` to stage a change.
   - If the query reveals a need for further investigation or a new task, use `task.create`.
5. **Progress Tracking**:
   - Use `observations.temporary.append` to record significant decisions, blockers, or findings during the process.

## Bounded Branches
- **If information is missing**: If `vault.search` and `vault.list` yield no relevant results, check if the information is in the `Agents/Alexandria/Inbox` or if a new research task is required.
- **If contradiction is found**: If multiple articles provide conflicting information, note the contradiction and use `vault.validate` to check the integrity of the relevant articles.

## Stop Conditions
- A definitive answer is formulated and verified.
- The query requires a capability not present in the current toolset.

## Completion Criteria
- The answer is provided to the owner via the interaction interface.
- The task is ended with `task.complete` using the appropriate status (`completed` or `failed`).

## Verification
- Ensure all answers are grounded in existing vault articles or verified sources.
- Verify that any proposed changes follow the `vault.propose` protocol.
