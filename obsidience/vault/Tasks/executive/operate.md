Produce and verify the owner's explicitly requested computer outcome through exact Task-authorized Tools, whether the request arrives in typed Chat or speech. The current request, conversation and controller Bindings identify its application and scope. Application-specific Knowledge supplies facts, never another Task or execution authority.

The controller's computer_outcome distinguishes launch, observation, focus, placement and in-application action. For action, computer_scope=input requests the input itself; state requests a resulting application state. An already open application and a request to start its match require in-application work, not another launch. One outcome may need ordered steps in the existing Runbook; each Tool remains one bounded operation.

Completion requires the current execution's matching evidence. Historical assistant text or earlier Tool delivery is not current state. Input completion requires an acknowledged click with a fresh post-image. State completion additionally requires the model to interpret a current post-action image and explicitly establish the requested state; an acknowledged click alone is insufficient.
