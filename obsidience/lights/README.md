# Native Matter lights controller

One stable `@matter/main` 0.17.9 `ServerNode` with `ControllerBehavior` owns the
fabric, peers, sessions and subscriptions. No WiZ fallback or second controller.
Fixture aliases become stable native peer IDs. The existing lights capability and visualizer use this controller. Music visualization
requires a Matter timing profile measured after commissioning; WiZ-era timing
profiles are rejected.

## Runtime and private storage

Install the exact dependency graph with `npm ci --ignore-scripts --no-audit`.
The user unit is `systemd/obsidience-lights.service`. It holds a `flock`
before controller startup and uses these private paths:

- `%t/obsidience-lights/control.sock`: one newline JSON request per connection,
  socket 0600, parent directory 0700.
- `%h/.local/state/obsidience-lights/*.enc`: native Matter state, AES-256-GCM
  encrypted with a new nonce and namespace-bound additional authenticated data
  per atomic write. Ciphertext is fsynced before rename, then the directory is
  fsynced. Authentication or persistence failure blocks further operations.
- `LoadCredentialEncrypted=matter-key:%h/.config/credentials/obsidience-matter-key.cred`:
  the 32-byte binary encryption key, generated by the installer and encrypted with
  user-scoped `systemd-creds`. Never replace this key while retaining fabric state.
  The driver reads only the private systemd credential file. Native fabric keys,
  node/session records and cleartext serialization exist in process memory only.
  The matter.js filesystem, config-file, argv and ambient-env loaders are disabled
  so native state cannot escape into its default storage directory.

The installer owns generating/preserving the encrypted credential and installing
this unit. Keep the key credential and encrypted fabric snapshot together in private backups.
The service suppresses dependency diagnostics because commissioning internals can
contain setup data. It emits only `ready`, `startup_failed`, or `runtime_failed`.
Protocol failures contain bounded safe codes, never raw dependency exceptions.
Restart is disabled: corrupt or unavailable storage must be diagnosed directly.

## Socket contract

Success: `{ok:true,result:{...}}`. Failure:
`{ok:false,error:{code:"..."},delivery:"not_dispatched"|"uncertain",mustNotReplay:true}`.
Malformed input is rejected before dispatch. Each connection accepts one request,
capped at 8192 bytes; 64 connections and eight pending requests per lane maximum.
Each fixture has a serialized lane; different fixture lanes may run concurrently.
Commissioning and discovery share the administrative lane.

Commands:

- `{command:"status"}` returns protocol, pinned library version, commissioned
  targets with nodeId decimal strings and available OnOff endpoint numbers.
- `{command:"discover",seconds:8}` performs bounded IP/mDNS discovery (1-30 s),
  returning public metadata only. Discovery requires an open commissioning window;
  a commissioned WiZ bulb normally does not advertise as commissionable.
- `{command:"commission",target:"window_lamp",pairingCode:"<private>"}` commissions
  that exact alias over IP with BLE disabled. Locally cached uncommissioned
  discovery records are removed first so discovery cannot retain a peerN ID instead
  of the fixture alias; commissioned peers are preserved. Manual codes are 11 or 21 digits.
  The code travels only through the protected socket and is never returned or
  logged. An already commissioned alias is rejected. Use the existing admin's
  multi-admin/share window when necessary; do not factory-reset bulbs for a code.
- `{command:"read",target:"window_lamp",endpoint:1}` returns a fresh native Matter
  Read, bypassing data-version filtering. Endpoint may be omitted only if exactly
  one OnOff endpoint exists. Native fields: `onOff`, `currentLevel`, `colorMode`,
  `currentX`, `currentY`, `currentHue`, `currentSaturation`, and
  `colorTemperatureMireds`, where the endpoint advertises them. Result also includes
  target, nodeId, endpoint and `fresh:true`.
- `{command:"set",target:"window_lamp",nodeId:"1",endpoint:1,level:128,color:{mode:"xy",x:20000,y:21000},readback:false}`
  checks exact nodeId and endpoint binding and validates every command before any
  dispatch. `onOff` is an optional strict boolean. Level is integer 0-254. Color
  is `{mode:"xy",x:0..65279,y:0..65279}`,
  `{mode:"hs",hue:0..254,saturation:0..254}`, or
  `{mode:"temperature",mireds:1..65279}`. Invalid values fail rather than clamp.
  Color and level commands use explicit `transitionTime:0`. With `onOff:true` and
  positive level, `moveToLevelWithOnOff` combines both without a separate On command.
  Otherwise optional native On/Off follows color and level. The device can clamp
  to its supported gamut/temperature/level limits. No mutation is replayed.
- `{command:"shutdown"}` accepts shutdown, drains current lanes, closes the sole
  controller and removes its socket. Systemd SIGTERM follows the same path.

Set result includes `delivery:"acknowledged"`, `commandsAcknowledged`,
`effectVerified:false`, `transitionTime:0`, target/nodeId/endpoint. With readback
omitted/true, `state` contains a fresh remote Read; the Python caller must compare
that state. With `readback:false`, only command acknowledgement is returned for
visualizer frames. Acknowledgement never proves physical illumination or no fade.
Pure On/Off behavior and every command type require real-bulb acceptance.

Use `pair.py FIXTURE_ALIAS` for a hidden TTY prompt or pipe a code from a protected
file into stdin; the code never appears in argv or environment. The helper accepts
`OBSIDIENCE_MATTER_SOCKET` only as a socket-path override. Lost responses report
uncertain delivery, never automatic retry.

Disconnected pending requests are dropped. Disconnect during a set stops remaining
commands after the current native command finishes. A dispatched Matter command
cannot be unsent. No client timeout releases a fixture lane early; restoration
enters the same lane after the previous command drains. There is no asserted
30-second total transaction bound: commands/read/reconnection use native budgets.
The caller must retain `cleanup_incomplete` and block new visualization while
restoration remains pending. A timeout never proves that a bulb did nothing.
