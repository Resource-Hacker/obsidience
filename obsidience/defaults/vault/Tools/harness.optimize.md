## Runtime

Run the exact `optimization_case` bound to Heimdall Audit with `{"case_id":"<exact SHA256>"}`. Microsoft AutoSaddler V2 owns diagnosis, structured candidate edits, retries, evaluation and selection. Executive trials use DeepSeek; specialist trials use their ordinary executor. All trial operations are intercepted before live dispatch.

## Contract

Cases are independently registered or captured at the committed Capability boundary. Each evaluation uses five distinct decision cases repeated five times, giving 25 observations per baseline or full candidate. Automatic cases pair the triggering rejection with four accepted controls from four other runs of the same Task/Tool, using the actual executable completion/proposal contracts. Insufficient current evidence waits for more controls; the optimizer cannot duplicate cases or author grading criteria. A successful dry validation does not publish Knowledge or repeat an action.

The Audit-selected model proposes changes; the affected Agent/Task model runs evaluations through the existing model owner. The native default is two session retries (three total attempts). Jobs allow three candidate iterations, a bounded rollout budget and fifteen minutes overall. Foreground demand cancels and joins inference; unpublished work can resume its exact checkpoint. STOP remains cancellation.

Every candidate must improve training behavior, pass every held-out case and preserve the existing Tool-count bounds. Latency can reject a candidate only for Executive evaluated with reasoning `none`, using the existing 25-percent-plus-200-ms allowance. Specialists and Executive with reasoning enabled are judged on correctness without a latency rejection; timing remains visible. This follows the affected Agent/Task's reasoning setting, not Audit's. Only the instruction body can change; links, metadata, grants and model settings remain frozen. The Tool returns `verdict`, `comparison`, `source_path`, `report_id`, and optionally a real `proposal`. That proposal is not deployment. After the Audit finishes, the existing Review authority revalidates the exact candidate and returned Tool receipt, then may publish under the owner's automatic instruction policy. Code and unsupported cases remain in Review; no ordinary wiki change is auto-approved by this capability.
